# Mini Hackathon: Rules & Guidelines

> "Build ethically, collaborate generously, and let working software speak for itself."

To maintain a competitive, fair, and enriching learning atmosphere, all participants in the Mini Hackathon must adhere to the following rules.

---

## 1. Original Work & Code Policy

```
ALLOWED:                                FORBIDDEN:
✅ Open-source libraries (React, npm)   ❌ Cloning existing complete projects
✅ Pre-trained models (Groq, HF)        ❌ Re-submitting previous hackathon code
✅ Boilerplates & starter templates     ❌ Modifying 2 lines of someone else's repo
✅ Public APIs & documented SDKs        ❌ Writing code before the official kickoff
```

1. **Fresh Development:** All project code, models, and UI logic submitted must be authored during the official duration of the hackathon sprint.
2. **Permissible Boilerplates:** Teams are permitted to use open-source frameworks, CSS component libraries (Tailwind, shadcn/ui), and project scaffolding tools (Create Next App, FastAPI skeletons).
3. **Pre-existing Code Prohibited:** Submitting a pre-built app developed prior to the event kickoff will result in immediate disqualification.
4. **Git Commit Timestamps:** Evaluators will inspect commit timestamps on GitHub. Repositories with a single massive commit containing a completed codebase at the start of the event will be flagged for investigation.

---

## 2. Team Composition & Academic Integrity

- **Team Size:** Teams must consist of 2 to 4 registered members. No individual may be registered with more than one team simultaneously.
- **Student Status:** All participants must be actively enrolled undergraduate students. College identification cards must be presented at the check-in desk.
- **Fair Contribution:** Every team member should have a defined role (e.g., UI, Backend, Research, Pitch) and be prepared to answer questions during evaluation.

---

## 3. Technology, Data & AI Ethics

- **Responsible AI Usage:** If utilizing Generative AI tools (ChatGPT, GitHub Copilot, iNSIGHTS AI), teams must be able to explain the underlying logic and system architecture. The team must own the engineering decisions.
- **Data Privacy & Scraping:** Projects scraping external websites or user data must comply with standard privacy ethics and robots.txt constraints. Do not harvest sensitive personal information or proprietary college databases without permission.
- **Intellectual Property:** Teams retain 100% full intellectual property (IP) and ownership of everything they create during hackathons and sprint events. All code should be open-sourced under an MIT or Apache 2.0 license.

---

## 4. Code of Conduct & Harassment Policy

Hackathon is dedicated to providing a safe, inclusive, and harassment-free environment for everyone, regardless of gender, sexual orientation, disability, physical appearance, race, or religion:

- **Professionalism:** Treat fellow participants, mentors, organizers, and judges with mutual respect.
- **Zero Tolerance:** Intimidation, harassment, offensive comments, or unwelcome personal advances will result in immediate expulsion from the venue without refund.
- **Reporting:** Any participant experiencing or witnessing misconduct should immediately notify an event organizer wearing the official organizer badge.

---

## 5. Disqualification Criteria

A team will be disqualified if:
1. They submit plagiarized code or pass off third-party proprietary software as their own.
2. They harass or intentionally disrupt other competitors.
3. They fail to submit their project repository and presentation link before the official code freeze deadline.
4. They tamper with venue networking equipment or conduct unauthorized cyber-attacks on campus infrastructure.
